# 外部业务系统接入与切换操作手册

> 适用项目：`E:\Java\java_code\agent-ticket-platform`  
> 外部系统参考：`E:\Java\java_code\sky-take-out - 副本`  
> 适用日期：2026-10-25  
> 核心原则：**外部业务系统通过适配器和受控工具接入，不复制它的 Entity、Mapper、数据库和业务 Service。**

---

## 1. 先明确当前真实状态

### 1.1 当前没有连接任何外部业务系统

目前 Agent 平台实际依赖：

```text
MySQL        agent_ticket
Redis 6379   权限缓存与工具幂等
Redis 6380   Redis Stack 向量检索
阿里云百炼   qwen-plus / text-embedding-v3
```

数据库中有两条外部工具元数据：

```text
external_dish_query
external_order_query
external_system = sky-take-out
```

但这只是**占位配置**：

- `TicketToolFacade` 没有暴露这两个 `@Tool` 方法；
- `AgentToolRegistry` 中没有 `external_order_query` 实现；
- 没有 `SkyTakeoutProvider`；
- 没有真正请求 `sky-take-out` 的 HTTP 客户端。

因此当前 Agent **不能查询外卖订单、菜品、配送或退款**。

### 1.2 为什么选用 `sky-take-out - 副本`

- `sky-take-out` 已经继续优化，接口和数据模型与当前 Agent 演示不匹配；
- `sky-take-out - 副本` 保留了当时能够配合演示的版本；
- 因此只把它当作**外部系统开发靶场和接口参考**，不能把它的业务代码合并进 Agent。

### 1.3 不合并代码的原因

| 维度 | Agent 平台 | 外卖平台 |
|---|---|---|
| 核心职责 | 工单、RAG、工具、审批、审计 | 订单、餐品、骑手、支付、商家 |
| 数据库 | `agent_ticket` | `sky_take_out` 等业务库 |
| 用户体系 | `sys_user` | 外卖平台员工/用户 |
| 变更频率 | Agent 工具和策略 | 交易业务 |
| 安全边界 | 工具审批与幂等 | 支付和退款强一致 |

如果直接共享数据库：

- Agent 可以绕过外部系统的业务校验；
- 外部表结构变化会直接破坏 Agent；
- 无法独立部署和回滚；
- 退款等写操作难以做幂等和审计。

## 2. 正确架构

```text
用户
  ↓
售后 Agent 平台
  ├─ TicketToolFacade
  ├─ ToolExecutor
  │   ├─ 权限
  │   ├─ 幂等
  │   ├─ 审批
  │   └─ 审计
  ↓
ExternalBusinessProvider（能力接口）
  ↓
SkyTakeoutProvider（适配器）
  ↓ HTTP/JSON
sky-take-out - 副本
  ├─ 订单查询接口
  ├─ 配送查询接口
  └─ 退款查询接口
```

### 2.1 两层边界

**能力层**：Agent 只关心“查订单”，不关心底下是外卖平台还是 CRM。  
**适配层**：负责把外部系统字段转换成平台统一的 DTO。

### 2.2 只读和写操作分开

- 只读：订单、配送、退款状态，走普通工具。
- 写操作：取消订单、退款、补券，必须走审批工具。

---

## 3. 当前建议接入的能力

先只接三个只读能力：

| 工具编码 | 能力 | 外部接口示例 |
|---|---|---|
| `external_order_query` | 按订单号查订单 | `GET /admin/external/orders/{orderNo}` |
| `external_delivery_query` | 查配送状态 | `GET /admin/external/deliveries/{orderNo}` |
| `external_refund_query` | 查退款状态 | `GET /admin/external/refunds/{refundNo}` |

不要一开始接：

- 全额退款；
- 取消订单；
- 修改地址；
- 补发优惠券。

这些写操作必须等只读链路稳定、审批和幂等验证完成后再接。

## 4. 接入前先检查外部系统

### 4.1 确认副本服务能启动

在 `sky-take-out - 副本` 中启动后端，确认端口，例如：

```text
http://127.0.0.1:8080
```

### 4.2 确认需要的接口存在

不要直接查外部数据库。应该调用 HTTP API。

如果副本没有面向 Agent 的只读接口，需要先在副本中增加只读 Controller，例如：

```java
@RestController
@RequestMapping("/admin/external")
@RequiredArgsConstructor
public class ExternalAgentController {

    private final OrderService orderService;
    private final DeliveryService deliveryService;

    /**
     * Agent 按订单号查订单。
     * 只返回工单处理所需字段，不返回完整用户隐私。
     */
    @GetMapping("/orders/{orderNo}")
    public Result<ExternalOrderVO> order(@PathVariable String orderNo) {
        return Result.success(orderService.getExternalOrder(orderNo));
    }
}
```

禁止：

- 给 Agent 一个可以执行任意 SQL 的接口；
- 把数据库账号密码交给 Agent；
- 返回身份证、完整手机号、支付卡号等敏感字段。

### 4.3 手工验证外部接口

```powershell
$externalToken = '你的外卖平台测试 token'

Invoke-RestMethod `
    -Method Get `
    -Uri 'http://127.0.0.1:8080/admin/external/orders/ORDER-202610250001' `
    -Headers @{ token = $externalToken }
```

只有外部接口能正常返回，才继续 Agent 适配器。

package com.atp.agent.external;

import com.atp.pojo.dto.external.ExternalDeliveryDTO;
import com.atp.pojo.dto.external.ExternalOrderDTO;
import com.atp.pojo.dto.external.ExternalRefundDTO;

/**
 * 外部业务系统能力接口。
 *
 * Agent 只依赖这个接口，不依赖具体外卖平台。
 * 以后切换 CRM、ERP，只要实现相同能力即可。

public interface ExternalBusinessProvider {

    /** 供应商编码，例如 sky-takeout-copy */

    ExternalDeliveryDTO getDelivery(String orderNo);

    /** 按退款单号查询退款 */

}

## 7.3 提供者注册表

文件：

```text
atp-agent/src/main/java/com/atp/agent/external/ExternalProviderRegistry.java
```

```java
package com.atp.agent.external;

import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Map;
import java.util.function.Function;
import java.util.stream.Collectors;

/**
 * 把所有 ExternalBusinessProvider Bean 按 code 注册。
 */
@Component
public class ExternalProviderRegistry {

    private final Map<String, ExternalBusinessProvider> providers;

    public ExternalProviderRegistry(List<ExternalBusinessProvider> providerList) {
        this.providers = providerList.stream()
                .collect(Collectors.toMap(
                        ExternalBusinessProvider::code,
                        Function.identity()
                ));
    }

    /**
     * 获取指定供应商；不存在时明确报错，不能回退到伪造数据。
     */
    public ExternalBusinessProvider require(String providerCode) {
        ExternalBusinessProvider provider = providers.get(providerCode);
        if (provider == null) {
            throw new IllegalStateException("外部系统未接入：" + providerCode);
        }
        return provider;
    }
}
```

## 7.6 外卖副本适配器

文件：

```text
atp-server/src/main/java/com/atp/server/external/skytakeout/SkyTakeoutProvider.java
```

```java
package com.atp.server.external.skytakeout;

import com.atp.agent.external.ExternalBusinessProvider;
import com.atp.pojo.dto.external.ExternalDeliveryDTO;
import com.atp.pojo.dto.external.ExternalOrderDTO;
import com.atp.pojo.dto.external.ExternalRefundDTO;
import com.atp.server.external.ExternalProperties;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

/**
 * sky-take-out 副本适配器。
 *
 * 它只负责 HTTP 调用和字段转换，
 * 权限、幂等、审批、审计仍由 ToolExecutor 统一处理。
 */
@Component
@RequiredArgsConstructor
public class SkyTakeoutProvider implements ExternalBusinessProvider {

    private static final String CODE = "sky-takeout-copy";

    private final RestClient externalRestClient;
    private final ExternalProperties properties;

    @Override
    public String code() {
        return CODE;
    }

    @Override
    public ExternalOrderDTO getOrder(String orderNo) {
        validateOrderNo(orderNo);

        return client()
                .get()
                .uri("/admin/external/orders/{orderNo}", orderNo)
                .retrieve()
                .body(ExternalOrderDTO.class);
    }

    @Override
    public ExternalDeliveryDTO getDelivery(String orderNo) {
        validateOrderNo(orderNo);

        return client()
                .get()
                .uri("/admin/external/deliveries/{orderNo}", orderNo)
                .retrieve()
                .body(ExternalDeliveryDTO.class);
    }

    @Override
    public ExternalRefundDTO getRefund(String refundNo) {
        if (refundNo == null || refundNo.isBlank()) {
            throw new IllegalArgumentException("退款单号不能为空");
        }

        return client()
                .get()
                .uri("/admin/external/refunds/{refundNo}", refundNo)
                .retrieve()
                .body(ExternalRefundDTO.class);
    }

    /**
     * 根据当前 provider 配置创建带 token 的客户端。
     */
    private RestClient client() {
        ExternalProperties.Endpoint endpoint = properties.getProviders().get(CODE);
        if (endpoint == null || endpoint.getBaseUrl() == null) {
            throw new IllegalStateException("sky-take-out-copy 未配置 base-url");
        }

        RestClient.Builder builder = externalRestClient.mutate()
                .baseUrl(endpoint.getBaseUrl());

        if (endpoint.getToken() != null && !endpoint.getToken().isBlank()) {
            builder.defaultHeader("token", endpoint.getToken());
        }

        return builder.build();
    }

    /**
     * 订单号只允许安全字符，避免拼出非法 URL。
     */
    private void validateOrderNo(String orderNo) {
        if (orderNo == null || !orderNo.matches("[A-Za-z0-9_-]{4,64}")) {
            throw new IllegalArgumentException("订单号格式不合法");
        }
    }
}
```

注意：`RestClient.mutate()` 的具体 API 以当前 Spring 版本为准；如果不行，直接使用 `RestClient.builder()`。

## 7.7 工具实现

文件：

```text
atp-server/src/main/java/com/atp/server/agent/tool/impl/ExternalOrderQueryTool.java
```

```java
package com.atp.server.agent.tool.impl;

import com.atp.agent.external.ExternalBusinessProvider;
import com.atp.agent.external.ExternalProviderRegistry;
import com.atp.agent.tool.AbstractAgentTool;
import com.atp.agent.tool.ToolContext;
import com.atp.agent.tool.ToolResult;
import com.atp.pojo.dto.external.ExternalOrderDTO;
import com.atp.server.external.ExternalProperties;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

import java.util.Map;

/**
 * 外部订单查询工具，只读。
 */
@Component
@Slf4j
@RequiredArgsConstructor
public class ExternalOrderQueryTool extends AbstractAgentTool {

    private final ExternalProviderRegistry providerRegistry;
    private final ExternalProperties properties;

    @Override
    public String code() {
        return "external_order_query";
    }

    @Override
    public Map<String, Class<?>> paramTypes() {
        return Map.of("orderNo", String.class);
    }

    @Override
    public ToolResult execute(Map<String, Object> args, ToolContext ctx) {
        String orderNo = str(args, "orderNo");
        if (orderNo == null) {
            return ToolResult.fail("订单号不能为空");
        }

        try {
            ExternalBusinessProvider provider =
                    providerRegistry.require(properties.getProvider());

            ExternalOrderDTO order = provider.getOrder(orderNo);
            if (order == null) {
                return ToolResult.ok(null, "没有查询到订单 " + orderNo);
            }

            String message = "订单 " + order.getOrderNo()
                    + "，状态：" + order.getStatus()
                    + "，实付：" + order.getPaidAmount()
                    + "，商家：" + order.getMerchantName();

            return ToolResult.ok(order, message);
        } catch (Exception e) {
            log.error("查询外部订单失败：orderNo={}", orderNo, e);
            return ToolResult.fail("暂时无法查询外部订单，请稍后重试");
        }
    }
}
```

其余配送、退款工具按同样方式实现。

/**
 * 查询外部订单。
 *
 * @param memoryId 会话记忆 ID，由 LangChain4j 注入
 * @param orderNo 外部订单号
 * @return 给模型转述的订单结果
 */
@Tool(
    name = "external_order_query",
    value = "按订单号查询外部外卖平台的订单状态、金额和商家。"
          + "只在用户询问外卖订单时调用。"
)
public String externalOrderQuery(
        @ToolMemoryId String memoryId,
        @P(value = "外部订单号", required = true) String orderNo) {

    Map<String, Object> args = new LinkedHashMap<>();
    args.put("orderNo", orderNo);

    // dispatch 会统一走 ToolExecutor 的权限、幂等、超时、审计
    return dispatch("external_order_query", args, memoryId);
}
```

```

模板文件 `application-dev.yml.example` 不能写真实 token：

## 9. 切换到其他业务系统

### 9.1 同能力、不同供应商

例如以后接另一个外卖系统：

1. 新增 `MeituanProvider implements ExternalBusinessProvider`。
2. `code()` 返回 `meituan-copy`。
3. 配置：

```yaml
atp:
  external:
    provider: meituan-copy
    providers:
      meituan-copy:
        base-url: http://127.0.0.1:8090
        token: ${MEITUAN_API_TOKEN}
```

4. 更新 `agent_tool.external_system`。
5. 重启应用。

工具编码和 Agent 提示不需要改变，因为能力相同。

### 9.2 不同业务领域

例如从“外卖”切换为“CRM”：

不要复用 `external_order_query`。新增能力包：

```text
crm_customer_query
crm_contract_query
crm_ticket_query
```

新增：

```java
public interface CrmBusinessProvider {
    CustomerDTO getCustomer(String customerId);
    ContractDTO getContract(String contractNo);
}
```

配置：

```yaml
atp:
  external:
    provider: crm-copy
```

并修改 `agent.tool_scope`，只让对应 Agent 看到 CRM 工具。

推荐的能力包表：

| 能力包 | 工具前缀 | 适用 Agent |
|---|---|---|
| 外卖售后 | `external_order_*` | 售后助手 |
| CRM | `crm_*` | 客户成功助手 |
| ERP | `erp_*` | 供应链助手 |

## 10. 写操作审批

外部写操作示例：

```text
external_order_cancel
external_refund_create
external_coupon_compensate
```

数据库配置必须：

```text
read_only = 0
need_approval = 1
max_retry = 0
```

流程：

```text
模型提出动作
→ ToolExecutor 返回 needApproval
→ ApprovalService 生成审批单
→ 主管审批
→ resume
→ ToolExecutor.executeApproved
→ 外部接口
```

幂等键不能只靠 `runId + step`，应包含：

```text
providerCode + externalResourceId + businessAction
```

否则同一订单重复审批可能重复退款。

## 11. 故障降级

外部系统不可用时：

- 返回“暂时无法查询外部订单”；
- 不编造订单状态；
- 不把失败包装成成功；
- 工单可转为“已挂起”；
- 将 traceId、订单号、错误类型写入日志。

不要在工具中直接抛出堆栈给模型。模型只应看到可读的失败原因。

## 12. 测试清单

### 12.1 只读工具

- [ ] 不存在的订单返回“没有查询到”
- [ ] 外部系统超时返回可读失败
- [ ] 非法订单号被拒绝
- [ ] Agent 未授权时返回“不具备该能力”
- [ ] 相同 run 重复调用命中幂等缓存
- [ ] 运行轨迹出现 `agent_run_step`
- [ ] 审计表有 `tool_call_log`

### 12.2 写工具

- [ ] 普通调用不会直接执行
- [ ] 生成 `pending` 审批单
- [ ] 审批拒绝不执行
- [ ] 审批通过 resume 执行一次
- [ ] 重复 resume 不重复执行
- [ ] 外部系统超时后状态为执行失败

### 12.3 切换

- [ ] `provider=none` 时工具明确失败，不调用旧系统
- [ ] 切换 provider 后只调用新 URL
- [ ] `agent.tool_scope` 不含旧业务工具
- [ ] 日志中能看到当前 providerCode

## 13. 回滚

### 13.1 禁用外部能力

```yaml
atp:
  external:
    provider: none
```

同时：

```sql
UPDATE agent_tool
SET enabled = 0
WHERE code LIKE 'external_%';
```

### 13.2 移除 Agent 工具授权

把 `agent.tool_scope` 恢复为不含外部工具的 JSON 数组。上线前应保留原值：

```sql
-- 示例：先记录原值
SELECT id, code, tool_scope FROM agent WHERE code = 'aftersale';
```

### 13.3 代码回滚

外部接入应全部通过适配器隔离，回滚时只需要：

1. 关闭配置开关；
2. 禁用工具元数据；
3. 回滚 `TicketToolFacade` 的 `@Tool` 方法；
4. 保留 Provider 类不影响其他业务。

## 14. 常见问题

### 14.1 Agent 说“当前助手不具备该能力”

原因：`agent.tool_scope` 没有包含工具编码。

修复：

```sql
SELECT tool_scope FROM agent WHERE code = 'aftersale';
```

### 14.2 工具存在但执行返回“外部系统未接入”

原因：`AgentToolRegistry` 没有找到 Provider Bean。

检查：

- Provider 是否有 `@Component`；
- `code()` 是否与配置一致；
- 包是否在 `com.atp` 扫描范围；
- 是否存在重复 `code()`。

### 14.3 一直查不到订单

检查：

- 是否连接了正确的外部系统；
- 订单号属于外卖系统还是 Agent 工单号；
- 外部接口是否返回 404；
- 请求头 token 是否有效；
- Provider 的 base-url 是否包含错误的前缀。

### 14.4 外部系统返回字段和 DTO 不一致

Adapter 负责字段映射，不要修改 Agent 内部模型去迁就外部字段。

## 15. 最终建议

1. **先只读，后写操作。**
2. **先订单查询，再配送，再退款。**
3. **先接一个 Provider，再抽象切换。**
4. **不要把外部平台 Mapper 复制进 Agent。**
5. **所有外部写操作必须走审批和幂等。**
6. **`provider=none` 必须能做到一键停用。**

一句话：

> Agent 平台负责决策、审批和审计；外部平台负责业务事实。两者只通过受控能力接口交互，不共享数据库。
