> 适用项目：`E:\Java\java_code\agent-ticket-platform`  
> 适用日期：2026-10-25  
> 当前实现：qwen-plus + LangChain4j 文档入库 + DashScope Embedding + Redis Stack 向量检索 + MySQL 分块元数据  
> 重要说明：**当前没有面向普通用户的知识库上传/查看页面**。现有可运行方式是“维护 Markdown 文件 + 执行入库脚本”；本手册后半部分给出后续 Web 管理功能的设计代码。

## 1. 先理解知识库到底在做什么

一次知识问答不是把整篇文档直接发给模型，而是分成两条链路。

### 1.1 入库链路

```text
docs/knowledge-base/*.md
        ↓ 读取文件
按 500 字切分，相邻块重叠 100 字
        ↓
计算 SHA-256，跳过重复内容
        ↓
调用 text-embedding-v3，得到 1024 维向量
        ↓
MySQL：写 kb_document、kb_chunk
Redis Stack：写 embedding:<vectorId>
        ↓
状态 pending → processing → ready
```

### 1.2 查询链路

```text
用户问题
   ↓
HybridRetriever
   ├─ 向量路：问题转向量 → Redis 向量检索
   └─ 关键词路：RediSearch 文本检索
   ↓
RRF 融合排序
   ↓
kb_retrieval_log 记录查了什么、命中了哪些 chunk、耗时多少
   ↓
kb_search 工具把片段交给模型
   ↓
模型生成回答，并带上 [1][2] 一类引用
   ↓
GET /agents/runs/{runId}/references 返回结构化引用
```

### 1.3 涉及的真实组件

| 组件 | 位置 | 作用 |
|---|---|---|
| 原始文档 | `docs/knowledge-base/` | 可版本管理的知识源文件 |
| 入库脚本 | `tools/seed-knowledge-base.ps1` | 切分、去重、Embedding、写 MySQL/Redis |
| 文档服务 | `atp-server/.../KbDocumentServiceImpl.java` | 已实现文件上传服务，但尚未暴露 Controller |
| 入库服务 | `atp-agent/.../KbIngestService.java` | 解析、切分、Embedding、落库 |
| 检索服务 | `atp-agent/.../HybridRetriever.java` | 向量 + 关键词 + RRF |
| 文档元数据 | MySQL `kb_document` | 标题、路径、状态、分块数 |
| 分块元数据 | MySQL `kb_chunk` | 正文、哈希、向量 ID、分类 |
| 向量数据 | Redis Stack `embedding:*` | 文本、1024 维向量、文档标题 |
| 检索日志 | MySQL `kb_retrieval_log` | 查询、命中、分数、耗时 |

## 2. 数据模型

### 2.1 `kb_document`

```sql
CREATE TABLE kb_document (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '文档主键',
    title       VARCHAR(200) NOT NULL                COMMENT '展示标题',
    doc_type    VARCHAR(16)  NOT NULL DEFAULT 'file' COMMENT 'file 类型',
    source_url  VARCHAR(500)     NULL                COMMENT '来源标识或 URL',
    file_path   VARCHAR(500)     NULL                COMMENT '本地绝对路径',
    status      VARCHAR(16)  NOT NULL DEFAULT 'pending'
                                                     COMMENT 'pending/processing/ready/failed',
    chunk_count INT          NOT NULL DEFAULT 0      COMMENT '分块数量',
    version     INT          NOT NULL DEFAULT 1      COMMENT '文档版本',
    error_msg   VARCHAR(500)     NULL                COMMENT '入库错误',
    uploaded_by BIGINT           NULL                COMMENT '上传人用户 ID',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (id)
);
```

每一步说明：

- `title`：用户最终看到的文档名，不要写文件名 UUID。
- `source_url`：用于标记来源；本项目的 seed 数据使用 `seed://knowledge/<文件名>`。
- `file_path`：必须以 `/` 或经过 SQL 正确转义的 `\` 保存。推荐统一使用 `/`，可避免 MySQL 把反斜杠当转义符。
- `status`：异步任务状态，不能只写 ready 就认为成功，还要检查 Redis 中是否存在对应向量。
- `chunk_count`：应与 `SELECT COUNT(*) FROM kb_chunk WHERE document_id=?` 相同。

### 2.2 `kb_chunk`

```sql
CREATE TABLE kb_chunk (
    id              BIGINT      NOT NULL AUTO_INCREMENT,
    document_id     BIGINT      NOT NULL,
    seq             INT         NOT NULL COMMENT '文档内序号，从 1 开始',
    content         TEXT        NOT NULL COMMENT '切分后的正文',
    token_count     INT         NOT NULL DEFAULT 0,
    vector_id       VARCHAR(128)    NULL COMMENT 'Redis 中的向量 ID',
    embedding_model VARCHAR(64)     NULL COMMENT 'text-embedding-v3',
    content_hash    VARCHAR(64) NOT NULL COMMENT 'SHA-256，用于去重',
    page_no         INT             NULL COMMENT 'PDF 页码',
    category        VARCHAR(64)     NULL COMMENT '业务分类',
    create_time     DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_content_hash (content_hash)
);
```

关键约束：

- `uk_content_hash` 保证相同内容不会重复入库。
- `vector_id` 必须与 Redis key 去掉 `embedding:` 前缀后的值完全一致。
- 如果数据库 ready 但 `vector_id` 在 Redis 不存在，检索就会缺失该分块。

### 2.3 Redis JSON 格式

每个分块在 Redis 中保存为一个 JSON：

```json
{
  "text": "分块正文",
  "vector": [0.013, -0.024, 0.031],
  "document_id": 22,
  "doc_title": "食品安全与投诉升级规范",
  "seq": 1
}
```

对应 Redis key：

```text
embedding:seed-22-1
```

索引结构由 LangChain4j 自动创建：

```text
索引名：embedding-index
类型：JSON
前缀：embedding:
字段：$.text AS text TEXT
字段：$.vector AS vector VECTOR
字段：$.doc_title AS doc_title TEXT
```

## 4. 添加一篇知识文档

### 第 1 步：创建 Markdown 文件

路径示例：

```text
E:\Java\java_code\agent-ticket-platform\docs\knowledge-base\06-food-safety.md
```

模板：

```markdown
# 食品安全与投诉升级规范

## 立即响应

用户反馈异物、变质、未熟、食物中毒等情况时，客服必须立即将工单优先级调整为紧急。

## 证据收集

请用户保留餐品、包装、订单小票或照片，记录食用时间、身体不适症状和是否就医。

## 退款与赔付边界

确认存在食品安全风险时，可优先执行整单退款。额外赔付、医疗费用和法律责任必须升级主管并走审批。
```

写作要求：

- 第一行用 `# 标题`。
- 每个业务规则用 `## 二级标题` 分开。
- 单段不要过长；一个段落最好只表达一个规则。
- 不要把答案写成含糊的“根据情况处理”，要写清条件、动作和边界。
- 不要在知识库中硬编码真实手机号、地址、身份证号等隐私。

### 第 2 步：登记文档元数据

脚本中的 `$metadata` 必须增加一行：

```powershell
$metadata = @(
    @{ File = '01-refund-policy.md'; Title = '退款与售后处理规范'; Category = '退款' },
    @{ File = '02-delivery-exceptions.md'; Title = '外卖订单配送异常处理手册'; Category = '配送' },
    @{ File = '03-sla-and-ticket.md'; Title = '工单处理与 SLA 规范'; Category = '工单' },
    @{ File = '04-account-coupon-invoice.md'; Title = '账号、优惠券与会员积分规则'; Category = '账号' },
    @{ File = '05-external-takeout.md'; Title = '智能外卖平台外部系统接入说明'; Category = '外部系统' },

    # File 是 docs/knowledge-base 下的文件名
    # Title 是检索结果和引用中展示的正式名称
    # Category 会写入 kb_chunk.category，便于后续按分类过滤
    @{ File = '06-food-safety.md'; Title = '食品安全与投诉升级规范'; Category = '食品安全' }
)
```

**注意**：每条记录之间必须有逗号，最后一条可以没有逗号。

## 5. 执行入库

### 5.1 标准 Docker 模式

```powershell
cd 'E:\Java\java_code\agent-ticket-platform'
& '.\tools\seed-knowledge-base.ps1' -RedisMode docker
```

脚本会执行以下步骤：

1. 读取 `QW-API-KEY`。
2. 检查 `mysql.exe` 是否存在。
3. 检查 Redis `PING` 是否返回 `PONG`。
4. 删除上一次由 seed 脚本写入的文档、分块和向量，只清理 `seed://knowledge/%`，不碰其他知识。
5. 读取每篇 Markdown。
6. 按 500 字切分，相邻块重叠 100 字。
7. 计算每个分块的 SHA-256。
8. 每 20 个分块调用一次 Embedding API。
9. `JSON.SET embedding:<vectorId>` 写入 Redis。
10. 写入 `kb_chunk`。
11. 更新 `kb_document` 为 `ready`。
12. 写入 FAQ 样例。

### 5.2 当前机器的 WSL 临时模式

```powershell
cd 'E:\Java\java_code\agent-ticket-platform'
& '.\tools\seed-knowledge-base.ps1' -RedisMode wsl
```

预期输出：

```text
document ready: 退款与售后处理规范 (id=17, chunks=1)
document ready: 外卖订单配送异常处理手册 (id=18, chunks=1)
document ready: 工单处理与 SLA 规范 (id=19, chunks=2)
document ready: 账号、优惠券与会员积分规则 (id=20, chunks=1)
document ready: 智能外卖平台外部系统接入说明 (id=21, chunks=1)
document ready: 食品安全与投诉升级规范 (id=22, chunks=1)

```

如果 Redis 不可用，脚本会在 `PING` 预检处直接失败，不会再把文档误标成 ready。

### 6.2 Redis 命令封装

```powershell
function Invoke-Redis {
    param([string[]]$Arguments)

    if ($RedisMode -eq 'wsl') {
        # 直接调用 WSL 中的 redis-cli，适合当前 Docker Desktop 修复期间使用
        $output = & wsl.exe -d $WslDistro -- $WslRedisCli -p $RedisPort @Arguments 2>&1
    } else {
        # 正常环境：进入 redis-vector 容器执行 redis-cli
        $output = & docker exec $RedisContainer redis-cli @Arguments 2>&1
    }

    if ($LASTEXITCODE -ne 0) {
        throw "Redis 命令失败：$($Arguments -join ' ') -> $($output -join ' ')"
    }
    return @($output)
}
```

这段代码的意义：把 Docker/WSL 两种运行方式的差异收敛在一个函数里，后面的 `DEL`、`JSON.SET` 不需要关心底层环境。

### 6.3 Redis 预检

```powershell
$redisPing = (Invoke-Redis -Arguments @('PING')) -join ''
if ($redisPing -notmatch 'PONG') {
    throw "Redis Stack 不可用，请先启动 Redis Stack"
}
```

必须使用 `-notmatch 'PONG'` 而不是只判断 `-eq 'PONG'`，因为 WSL 可能把本机 localhost 提示混入输出。

### 6.4 文本切分

```powershell
function Split-Text {
    param([string]$Text, [int]$Size = 500, [int]$Overlap = 100)

    # 统一换行，去掉首尾空白
    $normalized = $Text.Replace("`r`n", "`n").Trim()
    $chunks = [System.Collections.Generic.List[string]]::new()
    $start = 0

    while ($start -lt $normalized.Length) {
        $length = [Math]::Min($Size, $normalized.Length - $start)

        # 如果不是最后一段，优先在段落边界断开
        if ($start + $length -lt $normalized.Length) {
            $candidate = $normalized.Substring($start, $length)
            $breakAt = $candidate.LastIndexOf("`n`n")
            if ($breakAt -ge 220) { $length = $breakAt + 2 }
        }

        $piece = $normalized.Substring($start, $length).Trim()
        if ($piece) { $chunks.Add($piece) }

        if ($start + $length -ge $normalized.Length) { break }

        # 留 100 字重叠，避免规则被切在边界处而丢失上下文
        $start = $start + $length - $Overlap
    }
    return $chunks
}
```

### 6.5 调用 Embedding

```powershell
$body = @{
    model = $EmbeddingModel
    input = $batch                   # 一批最多 20 个文本
    dimensions = 1024                # 必须与 Redis 索引维度一致
    encoding_format = 'float'
} | ConvertTo-Json -Depth 5 -Compress

$response = Invoke-RestMethod `
    -Method Post `
    -Uri 'https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings' `
    -Headers @{
        Authorization = "Bearer $apiKey"
        'Content-Type' = 'application/json'
    } `
    -Body ([Text.Encoding]::UTF8.GetBytes($body)) `
    -TimeoutSec 60
```

注意：

- `QW-API-KEY` 只能来自环境变量，不能写死在脚本或 Git 中。
- Embedding 模型和维度必须与 `application-dev.yml` 一致。
- 模型或维度变化后，旧向量不能继续混用。

### 6.6 写 Redis

```powershell
$record = @{
    text = $content
    vector = $embeddings[$i]
    document_id = $documentId
    doc_title = $docMeta.Title
    seq = $seq
} | ConvertTo-Json -Depth 6 -Compress

$writeResult = (Invoke-Redis -Arguments @(
    'JSON.SET', $vectorKey, '$', $record
)) -join ''

if ($writeResult -notmatch 'OK') {
    throw "向量写入失败：$vectorKey -> $writeResult"
}
```

`JSON.SET` 返回 `OK` 才能继续写 MySQL。否则必须失败退出，不能把文档标记成 ready。

### 6.7 写 MySQL 分块

```powershell
$chunkSql = "USE agent_ticket;
INSERT INTO kb_chunk
(document_id, seq, content, token_count, vector_id,
 embedding_model, content_hash, category)
VALUES (
 $documentId,
 $seq,
 " + (SqlQuote $content) + ",
 $tokenCount,
 " + (SqlQuote $vectorId) + ",
 " + (SqlQuote $EmbeddingModel) + ",
 " + (SqlQuote $hash) + ",
 " + (SqlQuote $docMeta.Category) + "
);"
```

`vector_id` 必须与 Redis key 去掉 `embedding:` 前缀后一致。

### 6.8 最终状态

```sql
UPDATE kb_document
SET status = 'ready',
    chunk_count = 7,
    error_msg = NULL
WHERE id = 22;
```

只有以下条件全部满足才允许标记 ready：

- MySQL 中 `kb_chunk` 已写入。
- 每个 chunk 的 `vector_id` 非空。
- Redis 中对应的 `embedding:<vector_id>` 已存在。
- Redis 索引 `hash_indexing_failures = 0`。

@RestController
@RequestMapping("/kb/documents")
@RequiredArgsConstructor
public class KbDocumentController {

    private final KbDocumentService documentService;

    /**
     * 上传 PDF、Markdown 或 TXT。
     * 只有 kb:manage 权限允许写入。
     */
    @PostMapping(value = "/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
    @RequirePermission("kb:manage")
    public Result<Long> upload(
            @RequestPart("file") MultipartFile file,
            @RequestParam(required = false) String title,
            HttpServletRequest request) {

        Long userId = (Long) request.getAttribute(JwtTokenInterceptor.ATTR_CALLER_ID);
        try {
            return Result.success(documentService.upload(file, title, userId));
        } catch (IOException e) {
            throw new BaseException("知识库文件保存失败");
        }
    }
}

```java
public Long createFromText(String title, String content,
                           String category, Long userId) throws IOException {
    Path dir = Paths.get(uploadProperties.getUploadDir(), "kb", "text");
    Files.createDirectories(dir);

    Path file = dir.resolve(UUID.randomUUID() + ".md");
    Files.writeString(file, content, StandardCharsets.UTF_8);

    KbDocument document = new KbDocument();
    document.setTitle(title);
    document.setDocType("file");
    document.setFilePath(file.toString());
    document.setSourceUrl("text://" + document.getTitle());
    document.setStatus("pending");
    document.setVersion(1);
    document.setUploadedBy(userId);
    documentMapper.insert(document);

    ingestService.ingest(document.getId());
    return document.getId();
}
```

## 14. 常见错误

### 14.1 `QW-API-KEY 未配置`

```powershell
[Environment]::GetEnvironmentVariable('QW-API-KEY', 'User')
```

如果为空，在 Windows 用户环境变量中配置，重新打开终端后执行。

### 14.2 Redis `PING` 不返回 PONG

检查：

```powershell
docker ps --filter "name=redis-vector"
docker exec redis-vector redis-cli PING
docker exec redis-vector redis-cli MODULE LIST
```

### 14.3 `hash_indexing_failures > 0`

常见原因：

- `metadata-keys` 把数字字段错误配置成 TEXT；
- 向量维度与索引不一致；
- JSON 字段类型不正确。

当前正确配置只索引文本字段：

```yaml
metadata-keys:
  - doc_title
```

### 14.4 文档 ready 但检索不到

依次检查：

```sql
SELECT id, title, status, chunk_count FROM kb_document WHERE id = 22;
SELECT id, seq, vector_id FROM kb_chunk WHERE document_id = 22;
```

```powershell
docker exec redis-vector redis-cli EXISTS embedding:seed-22-1
docker exec redis-vector redis-cli FT.INFO embedding-index
```

`EXISTS` 必须返回 `1`，`num_docs` 必须与实际向量数量一致。

### 14.5 PDF 解析失败

- 确认文件不是扫描图片 PDF；
- 扫描 PDF 需要 OCR，当前 Apache PDFBox 不负责 OCR；
- 中文乱码时确认 PDF 字体和编码。

### 14.6 内容重复

`kb_chunk.content_hash` 有唯一索引。重复内容会被跳过，不重复消耗 Embedding。

## 16. 一句话总结

当前知识库是“**文件源 + 脚本入库 + Redis 向量检索 + Agent 工具调用**”；  
目标产品是“**管理员上传文件或文本 + 系统异步向量化 + 用户查看文档列表和全文 + Agent 检索引用**”。

本手册先保证当前流程真实可执行，再把 Web 管理功能作为下一阶段实现，不用数据库里“假 ready”的数据冒充已完成入库。
